# RUNBOOK — Vibe Coding System

Two parts:
1. **Step-by-step installation** of the system (deploy `staging/` → `~/.claude/`).
2. **Operational concept→code workflow** for each new project.

> ⚠️ Prerequisite: the `staging/` tree must have already been generated by the implementation
> plan (`docs/superpowers/plans/2026-05-18-vibe-coding-system.md`).
> Until `staging/` exists, this is the reference procedure — not executable.
> Every write step to `~/.claude/` is **HITL**: execute only with your explicit confirmation,
> always after backup.

---

## PART 1 — Installation

### Step 0 — Prerequisites

```bash
claude --version          # expected v2.1.59+ (auto memory, hooks prompt-based)
command -v jq             # required by hook scripts
command -v ruff black mypy 2>/dev/null   # Python formatter (optional, hook graceful)
command -v swift-format 2>/dev/null       # optional (Swift hook)
cd /Users/stefanoferri/Developer/vibe-coding-system
ls staging/               # should show: user/  plugin/  project-templates/
```

### Step 1 — Full backup of `~/.claude/` (mandatory)

```bash
TS=$(date +%Y%m%d-%H%M%S)
mkdir -p ~/.claude/_backup-$TS
cp -p ~/.claude/CLAUDE.md      ~/.claude/_backup-$TS/ 2>/dev/null || true
cp -p ~/.claude/settings.json  ~/.claude/_backup-$TS/ 2>/dev/null || true
cp -Rp ~/.claude/rules         ~/.claude/_backup-$TS/ 2>/dev/null || true
cp -Rp ~/.claude/agents        ~/.claude/_backup-$TS/ 2>/dev/null || true
cp -Rp ~/.claude/skills        ~/.claude/_backup-$TS/ 2>/dev/null || true
cp -Rp ~/.claude/hooks         ~/.claude/_backup-$TS/ 2>/dev/null || true
echo "Backup in ~/.claude/_backup-$TS"
ls -la ~/.claude/_backup-$TS
```

### Step 2 — Zone 1: global CLAUDE.md

```bash
# Compare with the current file BEFORE overwriting
diff -u ~/.claude/CLAUDE.md staging/user/CLAUDE.md | less
```
**HITL:** review the diff. On your OK:
```bash
cp staging/user/CLAUDE.md ~/.claude/CLAUDE.md
```

### Step 3 — Zone 1: settings.json (diff mandatory)

```bash
# JSON validity of the staged file
python3 -m json.tool staging/user/settings.json >/dev/null && echo "JSON OK"
# Diff vs live (shows: removal of bypassPermissions/Bash(*), auto+allowlist, attribution, hooks)
diff -u ~/.claude/settings.json staging/user/settings.json | less
```
**HITL:** approve the diff (this is the permission-posture change to auto+allowlist). On OK:
```bash
cp staging/user/settings.json ~/.claude/settings.json
python3 -m json.tool ~/.claude/settings.json >/dev/null && echo "settings live OK"
```

### Step 4 — Zone 1: path-scoped rules

```bash
mkdir -p ~/.claude/rules
cp staging/user/rules/*.md ~/.claude/rules/
ls ~/.claude/rules/        # expected: python swift typescript-react web-vanilla sql-migrations shell
```

### Step 5 — Zone 2: hook scripts

```bash
mkdir -p ~/.claude/hooks
cp staging/plugin/scripts/protect-files.sh ~/.claude/hooks/
cp staging/plugin/scripts/auto-format.sh   ~/.claude/hooks/
chmod +x ~/.claude/hooks/protect-files.sh ~/.claude/hooks/auto-format.sh
bash -n ~/.claude/hooks/protect-files.sh && bash -n ~/.claude/hooks/auto-format.sh && echo "script syntax OK"
```
(Hook registration is already inside the `settings.json` deployed at Step 3.)

### Step 6 — Zone 2: agents

```bash
mkdir -p ~/.claude/agents
cp staging/plugin/agents/*.md ~/.claude/agents/
# Re-validation
V="$HOME/.claude/plugins/cache/claude-plugins-official/plugin-dev/unknown/skills/agent-development/scripts/validate-agent.sh"
for f in ~/.claude/agents/*.md; do bash "$V" "$f" >/tmp/v 2>&1; grep -q "Validation failed" /tmp/v && echo "FAIL $f" || echo "OK $f"; done
```

### Step 7 — Zone 2: skills

```bash
mkdir -p ~/.claude/skills
cp -R staging/plugin/skills/* ~/.claude/skills/
ls ~/.claude/skills/   # 7 folders, each with SKILL.md
```


### Step 10 — Rollback (if something goes wrong)

```bash

cp -p  ~/.claude/_backup-$TS/settings.json ~/.claude/settings.json
rm -rf ~/.claude/rules ~/.claude/agents ~/.claude/skills ~/.claude/hooks
cp -Rp ~/.claude/_backup-$TS/rules   ~/.claude/ 2>/dev/null || true
cp -Rp ~/.claude/_backup-$TS/agents  ~/.claude/ 2>/dev/null || true
cp -Rp ~/.claude/_backup-$TS/skills  ~/.claude/ 2>/dev/null || true
cp -Rp ~/.claude/_backup-$TS/hooks   ~/.claude/ 2>/dev/null || true
```

## PART 2 — Operational concept→code workflow (for each new project)

> PHASE 1 and PHASE 2 in **separate sessions** (never mix interview and coding).

### PHASE 1 — Concept → Spec → Structure
1. `mkdir ~/dev/<name> && cd ~/dev/<name> && claude`
2. `/project-bootstrap <brief description>` — or manually:
   - `/interview-driver <description>` → answers → `SPEC.md`
   - generate `ARCH.md` (+ ADR-001..N) with the `architect` agent
   - `/claude-md-generator` → project CLAUDE.md (chooses among the 3 Zone 3 templates)
3. HITL gate after each step. `git init` + initial commit.

### PHASE 2 — Implementation (fresh session)
4. `/clear` or new session. Plan mode for scaffold → HITL → execute → commit.
5. For each feature:
   - `@"architect (agent)"` → ADR → **HITL**
   - in parallel (max 4): `@"coder (agent)"` (backend/frontend), `@"tester (agent)"`, `@"doc-writer (agent)"`
   - `@"reviewer (agent)"` → **HITL** commit
   - Conventional Commits → PR
   - `/clear` between unrelated features

### Per-project setup (from Zone 3 template)
```bash
cp -R <vibe-repo>/staging/project-templates/app-fastapi-react/. ~/dev/<name>/
# or web-vanilla-wordpress/ or ios-swiftui/
# customize: name, real stack, commands; add CLAUDE.local.md to .gitignore
```

## Security notes

- No step writes to `~/.claude/` without your explicit confirmation; backup always first (Step 1).
- Secrets (`GITHUB_TOKEN`) never inline: env vars only.
- The `protect-files.sh` hooks (deny) take precedence over any permission mode: layered defense even with auto mode.
- The live `~/.claude/settings.json` only changes at Step 3, after an approved diff.

## Amendment 2026-05-18 — Stop hook discarded

The `type: prompt` Stop hook was removed (live + staging): false positives
on intentional pauses caused loops. Only PreToolUse (protect-files) and PostToolUse
(auto-format) remain. If you want a Stop hook in the future, write it with a
loop-guard on `stop_hook_active` (see Anthropic hooks-guide); but for an interactive
flow with frequent pauses it is not recommended.
